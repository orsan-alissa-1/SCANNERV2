# Scanner V2

A team capstone project developed at Abu Dhabi University for network vulnerability assessment and reporting. The prototype combines Nmap service discovery, a local SQLite CVE database, service-to-MITRE ATT&CK mappings, and guidance generated by a locally hosted language model.

**Status:** Academic source archive. This repository preserves the submitted implementation with documentation added for review. It is not a ready-to-run distribution or a production security tool. Local resources from the original environment are excluded, and the application has known security and accuracy limitations.

## What the prototype implements

- A Flask web interface with login, a dashboard, scan reports, and user management.
- Nmap scans of IP addresses and CIDR ranges with service version detection.
- Approximate CVE lookups using detected service names and version strings.
- Service-based mappings to MITRE ATT&CK techniques.
- On-demand guidance through an Ollama API running the `llama3` model locally.
- Charts summarising stored CVEs and scan findings.

CVE matches are candidates for investigation. They do not establish that a host is vulnerable. Service-to-technique mappings provide reference context and do not demonstrate that an attack occurred.

## Running the project

Read [setup notes](docs/SETUP.md) before attempting to run the source. A fresh clone cannot start without restoring external resources and creating a new user database. No existing user database, credentials, or private scan history is distributed.

## Scope and limitations

The implementation uses approximate CVE matching and heuristic risk indicators. Its AI route selects random database CVEs as prompt context, which can produce unrelated guidance. It also has insecure development defaults and incomplete access and path controls. See [known limitations](docs/KNOWN_LIMITATIONS.md) for details. Use only in an isolated lab on systems you own or have permission to assess.
